# Дизайн: цена тура с признаком «от»

## Цель

Дать редактору тура два предсказуемых управления ценой:

1. Числовая цена всегда имеет суффикс `₽`.
2. Отдельный чекбокс «от» управляет отображением минимальной цены как `от 5000 ₽`.

Для значения `по запросу` чекбокс недоступен и признак «от» не применяется.

## Затронутый workflow

- Сущность: CMS-документ тура.
- Пользователь: редактор/администратор контента.
- Цель: сохранить корректную цену и опубликовать её на сайте.
- Текущий поток: `TourCatalogFields` формирует `CmsTourTextPatch`; `applyTourTextPatch` валидирует и сохраняет документ; `cmsDocumentToSiteTour` передаёт цену в публичную модель; публичные компоненты используют `useTourDisplayPrice`.
- Публикация: внешне виден опубликованный документ, поэтому новый признак должен пройти весь путь вместе с ценой.

## Модель данных

Сохранить существующее строковое поле `price` и добавить необязательное поле:

```ts
priceFrom?: boolean
```

Это отдельный признак, а не текстовый префикс. Он предотвращает двойное `от`, позволяет надёжно управлять чекбоксом и сохраняет обратную совместимость со старыми документами.

Существующие документы без `priceFrom` трактуются как `false`.

## UI редактора

- В секции основных полей цены рядом со строкой цены разместить чекбокс с подписью `от`.
- Чекбокс включён только для числовой цены.
- При вводе числовой цены значение нормализуется к формату с конечным `₽`.
- При переключении на `по запросу` `priceFrom` автоматически сбрасывается в `false`, а чекбокс скрывается или disabled; предпочтительно скрыть, поскольку он не применим к этому типу цены.
- При включении чекбокса отправляется patch `{ priceFrom: true }`; при снятии — `{ priceFrom: false }`.
- Существующие значения `5000` и `от 5000 ₽` не должны создавать двойной суффикс/префикс. Исторический текстовый `от` при миграции трактуется как `priceFrom: true`, а в `price` сохраняется числовая часть с `₽`.

## Публичное отображение

Общий форматтер в слое `useTourDisplayPrice`/смежном helper-е выдаёт:

- `price = "5000 ₽", priceFrom = false` → `5000 ₽`;
- `price = "5000", priceFrom = true` → `от 5000 ₽`;
- `price = "по запросу"` → `по запросу`, независимо от старого/ошибочного `priceFrom`.

Все публичные потребители, использующие общий display-price контракт, получают одинаковое поведение: карточки, детальная страница и Telegram.

`pricePrevious` не меняется в рамках этой задачи.

## Сохранение и обратная совместимость

- Добавить `priceFrom` в `CmsTourDocument`, `CmsTourTextPatch`, преобразование документа в patch и применение text patch.
- Zod-схема принимает отсутствие поля как `false` на уровне поведения; формат хранения остаётся совместимым с документами без нового поля.
- Нормализация цены должна быть идемпотентной: повторное сохранение не меняет уже нормализованное значение.
- Значения `по запросу` и пустое значение не получают суффикс `₽`.

## Тестирование

Добавить/обновить тесты до реализации:

1. Unit-тесты форматтера: числовая цена с/без `₽`, `priceFrom`, `по запросу`, старый текстовый `от`.
2. Тесты `TourCatalogFields`: чекбокс виден для числовой цены, скрыт для `по запросу`, корректно отправляет `priceFrom`, цена нормализуется без двойного суффикса.
3. Тест `applyTourTextPatch`/преобразования документа: новый признак не теряется на пути сохранения и публикации.
4. Регрессия публичного price highlight: отображение `от 5000 ₽` и доступное имя/aria-описание используют тот же итоговый текст.

## Не входит в scope

- Перевод цены из строки в числовой объект.
- Изменение `pricePrevious`.
- Изменение цен в расписании или CRM.
- Миграция всех старых документов отдельным скриптом; совместимость обеспечивается нормализацией при чтении/сохранении.
