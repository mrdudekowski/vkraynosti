# SEO V2 implementation plan

## Goal

Keep the public tour catalogue crawlable and semantically useful while making the loading layer user-only, preserving CMS publication rules, and establishing a repeatable SEO operating model.

## Evidence already collected

- Production crawl on 2026-09-09: 47 sitemap URLs, all HTTP 200; each checked URL had one H1, title, description, canonical, and no duplicate title/description in the crawl sample.
- Production 404 returned HTTP 404 and `noindex`; HTTP redirects to HTTPS and slash-normalized tour URLs behaved as expected.
- The static shell still contained the loading phrase in hidden HTML. This is a concrete crawler-noise issue and is addressed first.
- No Search Console or Yandex Webmaster account data is available in this workspace; no impressions, coverage, query, or CWV claims will be invented.

## Implementation slices

1. Make the boot splash content and progress semantics browser-runtime-only.
   - Files: `index.html`, `scripts/seo-static-shells.test.ts`, `scripts/seo-check.mjs`.
   - Verification: static shell test, `npm run seo:check`, `node --check public/boot-splash-runtime.js`.
2. Publish the evidence-based audit and operating documents.
   - Files: `docs/seo/SEO-AUDIT-AND-PLAYBOOK.md`, `SEO-CHANGELOG.md`, `SEO-SEMANTIC-MAP.md`, `SEO-PUBLISHING-CHECKLIST.md`, `SEO-ARCHIVE-CHECKLIST.md`.
   - Verification: links and commands reviewed against current scripts.
3. Keep date and publication lifecycle work explicit.
   - Do not invent departure dates or add fake `lastmod` values. CMS remains the source for dates, status, and prices.
   - Treat zero-future-date pages as valid landing pages with a clear next-date CTA, then validate through CMS data and owner metrics before changing copy globally.
4. Re-run local SEO guards and live production smoke checks.
   - Record dependency/build limitations separately from SEO evidence.

## Out of scope for this slice

- No CMS schema migration, URL redesign, backlink campaign, or automatic Product/Event markup without verified commercial/date fields.
- No forced sitemap `lastmod`; the current catalog lacks trustworthy per-route timestamps.
- No claim of indexing success without GSC/Yandex coverage evidence.
