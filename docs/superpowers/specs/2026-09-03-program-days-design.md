# Дни программы тура — спецификация

## Цель

Добавить редактору явный выбор `День 1`, `День 2` и последующих дней в соответствии с длительностью тура, сохранив данные старых туров и корректно передав это поле через CMS/API в публичный сайт.

## Контракт данных

Каждый пункт программы хранится как:

```ts
type ProgramStep = {
  day: number;
  timeLabel: string;
  description: string;
};
```

`day` — целое число не меньше 1. Для обратной совместимости входящие пункты без `day` нормализуются в `day: 1`. Существующие поля `timeLabel` и `description` не меняются.

## Редактор

`ProgramSection` получает `durationDays`. Над списком отображается горизонтальный переключатель дней от 1 до выбранной длительности тура. Активный день фильтрует список пунктов. Кнопка добавления создаёт пункт с `day`, равным активному дню.

Если длительность не задана, доступен только День 1. Если длительность уменьшена, пункты с `day` больше новой длительности не удаляются автоматически: редактор видит предупреждение и может перенести их в доступный день или вернуть длительность.

Перемещение пунктов работает только внутри выбранного дня. Существующий мобильный режим перестановки через drag-handle сохраняется.

## Сохранение и публикация

Нормализация применяется на границах:

- парсер CMS добавляет `day: 1` отсутствующим значениям;
- `patchFromDocument` переносит `day` в локальный draft;
- `applyTourTextPatch` валидирует и сохраняет `day`;
- преобразования CMS ↔ site сохраняют `day` без потери.

Пункты сортируются стабильно: сначала по `day`, затем сохраняется текущий порядок внутри дня.

## Публичный вывод

Публичная программа группируется по `day`. Для однодневного тура заголовок дня не показывается, чтобы сохранить текущий внешний вид. Для многодневного тура показываются секции `День 1`, `День 2` и так далее только для дней, содержащих пункты.

## Валидация и ошибки

- `day` должен быть целым числом от 1;
- пункты с пустым временем или описанием продолжают блокировать публикацию по существующим правилам;
- пункты за пределами длительности не удаляются автоматически и явно отмечаются в редакторе;
- некорректные значения `day` отклоняются на уровне схемы/patch, а не silently исправляются.

## Тестовая стратегия

Покрываются следующие сценарии:

1. Старый пункт без `day` нормализуется в День 1.
2. CMS patch сохраняет `day` и не меняет остальные поля.
3. Переключатель отображает дни согласно `durationDays`.
4. Добавление пункта в активный день записывает правильный `day`.
5. Перемещение не смешивает пункты разных дней.
6. Уменьшение длительности не удаляет пункты сверх лимита и показывает предупреждение.
7. Публичное преобразование сохраняет и группирует дни.
8. Однодневный публичный вывод остаётся совместимым с текущим отображением.

## Границы этапа

В этот этап не входят изменение формата расписания выездов, миграция исторических JSON-файлов вручную и изменение визуального дизайна остальных секций админки.
